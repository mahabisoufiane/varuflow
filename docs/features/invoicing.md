# Swedish Invoice Requirements

Swedish invoices have specific legal requirements under the **Swedish VAT Act (Mervärdesskattelagen, ML)** and **European VAT Directive 2006/112/EC**. This document covers what is required, what Varuflow implements, and what is still missing.

---

## Legal Requirements for Swedish B2B Invoices

Under Swedish law, a VAT invoice must include:

| Field | Requirement | Status in Varuflow |
|-------|-------------|-------------------|
| Invoice number (sequential) | Required | Done |
| Issue date | Required | Done |
| Due date | Required | Done |
| Seller name and address | Required | Done |
| Seller organisationsnummer | Required | Done |
| Seller VAT number (SE + 12 digits) | Required | Done |
| Buyer name and address | Required | Done |
| Buyer organisationsnummer | Required for B2B | Done (optional field) |
| Buyer VAT number | Required for VAT B2B | Done |
| Description of goods/services | Required | Done |
| Quantity and unit | Required | Done |
| Unit price excl. VAT | Required | Done |
| VAT rate (%) | Required | Done |
| VAT amount per rate | Required | Done |
| Total excl. VAT | Required | Done |
| Total VAT | Required | Done |
| Total to pay | Required | Done |
| Currency | Required if not SEK | Done |
| Payment terms | Recommended | Done (30-day default) |
| **Bankgiro or Plusgiro number** | **Required for payment** | **MISSING** |
| **OCR number (payment reference)** | **Required for automated reconciliation** | **MISSING** |
| Payment due date | Required | Done |

## Critical Missing Fields

### Bankgiro / Plusgiro

Swedish businesses receive payments via **Bankgirot** (Bankgiro) or **Plusgirot** (Plusgiro) rather than standard IBAN bank transfers for domestic payments.

The seller's Bankgiro number (format: `NNN-NNNN` or `NNNN-NNNN`) or Plusgiro number must appear on the invoice so the buyer knows where to send the payment.

**Current state:** The PDF generator hardcodes `"bankgiro": "123-4567"` as a placeholder.

**What needs to be built:**
1. Add `bankgiro` and `plusgiro` fields to `Organization` model
2. Migration: `ALTER TABLE organizations ADD COLUMN bankgiro VARCHAR(10), ADD COLUMN plusgiro VARCHAR(10)`
3. Update onboarding and settings to collect these values
4. Wire them into `pdf_generator.py`

### OCR Number (Payment Reference)

The **OCR number** (Optisk teckentolkning — optical character recognition) is a structured payment reference that Bankgirot uses for automated reconciliation. When buyers pay via bankgiro and include the OCR number, the seller's accounting system automatically matches the payment to the correct invoice.

OCR numbers follow the **BGC (Bankgirocentralen) specification**:
- Based on the invoice number
- Padded/prefixed per customer agreement
- Ends with a **Luhn check digit** (MOD-10)
- Maximum 25 digits

**Format example:** Invoice number `1042` → OCR number `10423` (where 3 is the Luhn check digit)

**What needs to be built:**
1. Add `ocr_number` column to `Invoice` model
2. Create `backend/app/services/ocr_generator.py` with BGC Luhn calculation
3. Auto-generate OCR number on invoice creation
4. Print OCR number in the payment section of the PDF
5. Optionally generate a Bankgirot QR-kod (betalningsuppmaning) image for the PDF


## VAT Rates (Sweden)

| Rate | Category |
|------|----------|
| 25% | Standard rate (most goods and services) |
| 12% | Food, restaurants, hotel accommodation, artist services |
| 6% | Books, newspapers, passenger transport, cultural events |
| 0% | Export, intra-EU B2B (reverse charge), medical care |

The VAT engine in `backend/app/services/vat.py` handles all rates including intra-EU reverse charge (Article 138 VAT Directive).

---

## Reverse Charge (Omvänd skattskyldighet)

For B2B sales within the EU where the buyer is VAT-registered:
- VAT rate = 0%
- Invoice must state: *"Reverse charge — Article 138 VAT Directive"*
- Buyer's VAT number must be on the invoice

Varuflow's VAT engine resolves this automatically based on seller country, buyer country, and buyer VAT number.

---

## Invoice Numbering

Swedish law requires invoices to be **sequentially numbered** with no gaps. Varuflow auto-increments invoice numbers per organization. Numbers cannot be reused or skipped.

Format: configurable prefix + sequential number (e.g., `INV-2024-0042`)

Customise invoice layout at **Settings → Invoice Templates**. You can set:
- Company logo
- Header text
- Footer text (payment instructions, terms)
- Color scheme

Changes apply to all new invoice PDFs. Existing PDF files are not regenerated.

## SIE4 Accounting Export

For end-of-year accounting, export all invoices as a SIE4 file:

```
POST /api/accounting/sie4-export?year=2024
```

Returns a CP437-encoded `.SI` file compatible with Fortnox, Visma, and other Swedish accounting software. Uses BAS 2024 chart-of-accounts (accounts 1510, 2610, 3000).
